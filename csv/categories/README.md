# Model catalog by graph category

Generated by `uv run --with gguf python tools/split_model_catalog.py --check`. The `--with gguf` part also validates the GGUF key names in the specs. Don't edit these files by hand. Fix the source CSVs in `csv/` and regenerate.

- `<category>/<format>.csv`: one row per model. A category groups models whose computation graph is built the same way. Columns that are empty for every row in a file are dropped.
- `<category>/metadata_spec.json`: the target output is `tensormorph-viz-graph` v1 (see `json/*.json`).
  - `dims` maps each output dim symbol (D, V, F, H, Hkv, Dh, Dq, Dkv, E, Fe, QR, KR, ...) to `[config.json expression, GGUF KV expression]`. The self-check confirms these symbols cover every dim used in the 8 example graphs.
  - `attrs` holds the other hyperparameters (layers, eps, rope, routing).
  - `safetensors` and `gguf` list the header fields that feed `tensors[].checkpoint_key`, `shape` and `dtype`.
  - In GQA graphs `H` is the number of query heads per KV group. In MHA and MLA graphs it is the total head count.
- `all_models.csv`: the merged master file with every column. `index.csv`: row counts per file.

## Merge rules
- Dedupe key: `huggingface_model_id`. There are 29,779 unique ids across `csv/*.csv`, and each id lands in exactly one category/format file.
- Per column, the first non-empty value wins in this order: deepseek_extended, deepseek, hf_llm_vlm, timm, nlp_extended, nlp, diffusers_extended, diffusers. `notes` from every source are joined with ` || `. `sources` and `families_seen` record where each row came from.
- `hf_open_weight_models.csv` is skipped because it is exactly hf_llm_vlm plus timm (the self-check verifies this).
- Structured columns are parsed from `notes`: `num_layers` (L=), `hidden_size` (d=), `num_attention_heads` (H=), `num_kv_heads` (KV=), `routed_experts`, `experts_per_token` and `shared_experts`, `params_total`, `lm_model_type`, `gguf_architecture`, and the `graph_flags` field (mla, sliding_global_attention, linear_attn_ssm, multimodal, trust_remote_code, gguf_llamacpp_names, ...).
- `metadata_origin`: where the hyperparameters come from. The value is the model's own config.json, `base_model <id> config.json` (common for GGUF repos), or the GGUF header.

## Routing
- Decoder families (Dense, MoE, Hybrid, Hybrid MoE) go to `decoder_*`. They go to `multimodal_vlm` instead when the family label or the `multimodal:` note says so. On the 1,143 ids shared by the nlp and hf_llm_vlm sources, the note agrees with the explicit Multimodal/* label 93% of the time.
- The multimodal signal is the union of all sources. About 23 ids that hf_llm_vlm labels non-multimodal still go to `multimodal_vlm` because the nlp note flags them.
- Encoder and encoder-decoder rows with a `multimodal` flag stay in `encoder` / `encoder_decoder`, and the flag is kept as a column.
- `safetensors+gguf` rows go to `safetensors.csv`. `pytorch_bin` and `pytorch_pickle` go to `pytorch.csv`. `tf_h5` and `flax_msgpack` go to `other.csv`.
- `classic_nlp` (spaCy, Flair, fastText, Stanza, CTranslate2) can't produce a tensor-program graph. These rows are kept so nothing is dropped.
- `unknown`: the family has to be derived from tensor names and shapes first, then the row moves to a real category.
